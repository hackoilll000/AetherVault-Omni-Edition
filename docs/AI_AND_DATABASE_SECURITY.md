# AI & Database Integration Security Specification

This document outlines the security model for user-provided AI models and database connections in AetherVault.

---

## 1. User-Provided Credentials Policy

- **No Developer API Keys**: The developer does not provide shared or paid API keys. Users supply their own API keys (e.g. Google Gemini, OpenAI, Anthropic).
- **Direct Client-to-Provider Requests**: Requests travel directly from the user's execution environment to the AI provider endpoint via HTTPS.
- **Cost Transparency**: Usage charges apply directly to the user's provider account.

---

## 2. Database Integration & Parameterized Query Rules

- **Read-Only Mode by Default**: Database connections default to read-only access to prevent accidental data modification.
- **Parameterized Queries**: All database queries generated by AI tools or bots MUST use parameterized SQL inputs (`%s`, `?`) to prevent SQL injection vulnerabilities.
- **Allowed Tables List**: Users explicitly configure an allowlist of accessible tables/views (e.g. `users, public_logs`). Access to system tables is blocked.

---

## 3. Tool Permissions & Access Control Lists (ACL)

AI tools (Database lookup, Web search, File reading) enforce strict permission checks:
1. **User Authentication**: The requesting Telegram user ID must match the bot owner's configured Telegram User ID list.
2. **Explicit Consent**: Destructive operations require explicit user confirmation before execution.
